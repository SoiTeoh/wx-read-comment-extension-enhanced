# U2 · 阅读位置与键盘操作

日期：2026-10-12。已完成本地开发和验收，未推送、未升级版本或发布新包；U3–U6 未开始。仅作用于上下滚动插件增强。

## 滚动条与圆角统一

用户指出 U1 截图的左侧卡片与右侧滚动区风格不一致。原因是 Windows Chromium 的原生滚动槽背景、上下箭头与端部沿用系统外观，宽白槽打断了插件的 tonal 配色和 24px 圆角。

现在仅对插件 popup 和侧栏设置 8px 宽滚动条：轨道透明，滑块使用已有主题色和圆角，上下各留 20px，移除箭头和不透明角落。保留真实鼠标拖动、滚轮与键盘滚动，没有伪造滚动控件，也不修改微信读书官方面板。

## 阅读位置保持

- 在操作官方字号滑块或切换侧栏前，保存当前已映射正文组、组内 rect 序号和屏幕纵坐标。窗口或 Reader 布局失效时也尝试保存可用锚点。
- 锚点来自既有原生映射对应的划线节点，不使用 DOM Range、文本猜测或新的正文匹配。没有视口内映射则不强行选择远处评论。
- 重新映射后等待 350ms 的布局稳定期，再将相同划线恢复到原屏幕位置。随后若又发生布局失效，旧恢复任务不会执行；整个恢复限于当前章、当前会话且不超过 2.5 秒。
- 实测发现真实 Reader 的画布坐标和绘制宿主有偏移，故不能直接把画布坐标当成屏幕坐标。实现改用已映射划线的实际屏幕几何，并在官方控件 pointerdown 时预先捕获，避免新字号重排后才保存位置。回归夹具也加入了绘制宿主偏移。
- 正文滚轮、触摸、导航按键及拖动页面滚动条会取消等待中的恢复；插件列表或原生面板内部滚动不会误取消正文锚点。
- 回复打开前保存正文、popup 和侧栏位置。原生详情关闭后先只读同步状态，再恢复列表位置与触发按钮焦点；若用户已主动导航，则不抢回位置。若正文布局已变化，则不恢复旧正文像素值。
- 这是尽量保持同段阅读位置，不承诺任意字形换行后都锚定同一个字；不做跨章阅读进度持久化。切章、切书或退出纵向后清理恢复任务。

## 快捷键

侧栏设置新增“启用阅读快捷键”，默认关闭，开启状态保存在原有本地设置中。

| 按键 | 行为 |
| --- | --- |
| Alt+Shift+C | 打开视口附近已映射想法，侧栏关闭时也可用 |
| Alt+Shift+Y | 复制当前 popup 已核实的原文，复用原文操作按钮的校验与反馈 |
| Esc | 沿用关闭 popup 并返回触发位置的行为；插件打开原生回复时不抢占其 Escape |

新增组合键不处理重复按键、输入法组合输入、其他修饰键、输入框／可编辑内容、原生面板及可见官方遮罩。能力未核实、按钮禁用、划线隐藏或没有附近映射时不执行相应操作。不会用快捷键点赞或提交回复。
