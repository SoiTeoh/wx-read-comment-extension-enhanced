# I1 · 横向 Reader 适配验收

日期：2026-10-10。范围仅为 `wx-read-comment-extension-enhanced` 的增强分支开发代码，已发布版本仍为 v1.4.0-beta.1。

## 实现

横向页面使用独立的 `HorizontalReader`。它没有纵向 Reader 的完整映射方法组合，因此新增独立适配层，沿用原生对象和原生坐标，不重建 EPUB，不做模糊文本匹配。

- Reader 发现使用有界 Vue／webpack 缓存遍历；支持现代 JSONP entry 与旧 callback 捕获，不依赖模块编号。
- `getCurrentDisplayRenderContents()` 读取当前双页对象；原生内容工具的 `findObjsInOffsetRange`、`getRectsByContentObjs` 完成定位。
- 双页可能显示不同章节，且每章 offset 可重叠。内容先按章节过滤，再保留原生 chapterUid 的类型传给原生工具。
- 页码、可见章节、渲染版本、布局尺寸与变化计数参与缓存判断；翻页、切章或 Reader 更换清理旧映射。
- `GET_READER_INTERACTION_CONTEXT` 仅返回书籍／章节、模式、可见章节、当前左右页索引、布局版本及有效的 `{chapterUid, range, text}` 原生选区。选区来自原生操作对象，不从 DOM 猜测正文。
- 观察原生选区及翻页方法时保留调用对象、参数、返回值和异常；卸载旧实例时恢复原始属性描述符，不覆盖原生后续替换。不可观察时返回空选区，原生阅读继续工作。
- 跨章节选区、过期布局、切书和窗口尺寸变化均清空选区。未读取或保存账号、Cookie、Token。

## 本地真实登录态验收

通过提升权限的 `exec_command` 启动 headed Playwright Chromium，使用用户已扫码登录的本地测试 profile；桌面窗口可见。测试《明朝那些事儿（全集）》，全过程关闭插件右侧评论栏，不触发个人划线写入、点赞、发布或 AI 提问。

| 场景 | 观察结果 |
| --- | --- |
| 横向双页跨章节 | 版权信息左页 381、第一章右页 382；兼容状态 READY，当前章节 123 条接口评论、16 组 range 成功定位 |
| 评论弹窗 | 点击插件 badge 打开现有公开评论 popup；关闭及 Escape 正常，UI 风格保持不变 |
| 真实鼠标拖选右页 | 原生工具栏保留，选区返回章节 382、range 472–480，文字为「们从一份档案开始」；没有绑定到左页 381 |
| 原生下一页 | 页索引从 0／1 到 2／3，旧选区清空；章节更新为 382，491 条接口评论中当前双页 61 组 range 定位成功 |
| 窗口缩放 | 1440×1000 → 1300×900 后重新分页，状态仍为 READY，44 组当前页 range 成功定位 |
| 原生字号 | 字号 level 2 → 3 后重新排版，24 组当前页 range 定位成功；随后恢复 level 2 |
| 上下滚动回归 | 切回纵向 Reader，状态 READY，491 条接口评论、165 组 range 定位成功；再切回横向仍可打开 popup |
| 稳定页性能 | 布局稳定后等待，不增加 bridge 映射计数和布局版本 |

这些是当次真实接口返回的数量，不能当作平台全部评论总数。横向仅映射当前显示页的当前章节，其他页范围未定位属于预期；双页跨章时另一章的评论在原生推进当前章节后加载。选区仍能正确标明右页所属章节。
