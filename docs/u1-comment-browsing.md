# U1 · 长评论与大量想法

日期：2026-10-12。优先级最高的评论浏览改进已完成。本地开发尚未发布，版本仍为 v1.5.0-beta.1；U2–U6 继续按 README 的阶段顺序推进。

## 行为

- 同段 popup 首批显示 30 条公开想法，顶部计数仍是完整数据总数。用户点击“加载更多想法”追加最多 30 条，并显示已渲染数量；已显示卡片不销毁、不重新绑定互动。
- 加载更多只使用此前已加载的章节列表，不请求接口、不重新映射正文。不是回复分页，也不是新的网络分页。
- 侧栏和 popup 中超过 600 字符或超过 8 行的评论默认折叠为 6 行。点击“展开全文”显示完整内容，点击“收起全文”折叠；保留原文数据和完整 DOM 文本，搜索继续匹配全文。
- 侧栏全文展开按钮阻止卡片定位事件冒泡，键盘 Enter 可操作；筛选与清除筛选保留同条评论的全文展开状态。
- 同一章节、同一正文组重新打开 popup，恢复已加载数量、全文展开状态和 popup 内部滚动位置。只在当前页面内存保留最近 20 个组，切章、切书及退出纵向时清空；不持久化书籍正文。
- 最后一批不满 30 条时，加载按钮收起并将键盘焦点交给第一张新卡片的按钮，避免焦点落到隐藏按钮。
- 本阶段保持原有颜色、圆角及日夜模式。没有侧栏虚拟化，也没有跨字号或跨章节的原文阅读锚点恢复；后者归 U2。

## 验收

完整受控验收通过，最终共 68 项离线测试、63 项 Chromium 场景（既有 56 项加 U1 的 7 项），TypeScript 和生产构建通过。

U1 场景覆盖：侧栏全文及键盘操作、800 条想法首批只创建 30 张 popup 卡片、逐批追加保留原 DOM、关闭重开恢复展开与滚动位置、稳定滚动和主题变化零额外请求／映射、切章清理、65 条最后一批焦点，以及窄窗口原生回复入口。受控写请求为零，800 条首批打开本机约 203ms；性能回归上限为 5 秒，不代表真实接口延迟保证。

真实登录态使用 Windows 桌面 headed Playwright Chromium，在《明朝那些事儿（全集）》“第一章 童年”纵向页面验收。已加载 490 条想法，发现 708／1313 字符的可定位长评论；验证完整展开、关闭重开后展开状态保留，popup 内滚动位置恢复为 260px。期间没有新增评论列表或单条读取，也没有账号写请求。本章同组最多 28 条，大组按需加载由 800 条受控夹具验证，没有将其声称为真实大组验收。

## 发布包保护

验收构建现使用 `node utils/build.js --no-zip`，只更新开发 `build`，不覆盖已有发布安装 ZIP。明确执行 `npm run build` 仍生成版本命名的发布包。

本次首次构建曾覆盖本地 v1.5 ZIP；已从发布标签重建，并核对运行文件与原记录，恢复原 ZIP 字节。最终 SHA-256 仍为：

```text
eacfd8e93482878d383dc1df2f063ddc99e92b383e7589d70ad525b0b869b339
```

因此，本地 `build` 包含 U1，现有 v1.5 ZIP 保持原已交付内容；不要将开发构建当成已发布 U1 安装版。
